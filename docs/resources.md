# Curated resources and license ledger

**Status:** research reference for the documentation checkpoint, 23 October 2026. This is a shortlist for PandaByte’s confirmed engineering-studio direction, not a claim that the repositories with the most stars are objectively “best.” Star/fork counts are dated adoption signals, not quality or maintenance guarantees. No app dependency, skill collection, or template was installed or initialized for this ledger.

## Recommended site foundation

Keep one Next.js App Router application with React and TypeScript. Use Tailwind CSS for utility styling and semantic light/dark CSS variables. Build pages from selected [shadcn/ui](https://github.com/shadcn-ui/ui) components, keeping their source in the app; use [Radix Primitives](https://github.com/radix-ui/primitives) where its accessible, unstyled interaction primitives are the chosen base. Avoid adding a second component kit. Use [Heroicons](https://github.com/tailwindlabs/heroicons) for icons. Start interactions with CSS; add [Motion](https://github.com/motiondivision/motion) only for a reviewed interaction that benefits from coordinated animation, and follow its [reduced-motion guidance](https://motion.dev/docs/react-accessibility).

Use [Next.js](https://github.com/vercel/next.js) and [React](https://github.com/facebook/react) (MIT) with [TypeScript](https://github.com/microsoft/TypeScript) (Apache-2.0). The application preference for MIT libraries has explicit exceptions: [InsForge](https://github.com/InsForge/InsForge) is Apache-2.0 and is the confirmed database/storage platform; the PostgreSQL engine uses the [PostgreSQL License](https://www.postgresql.org/about/licence/), not MIT. [Playwright](https://github.com/microsoft/playwright) is Apache-2.0 and remains a suitable optional browser-test tool. Preserve all applicable notices; an open-source license does not describe hosted-service pricing or terms.

Use InsForge’s typed SDK for ordinary data work and reviewed SQL/RPC for transactions, with custom Next.js APIs owning validation, authorization, and commerce behavior. Keep the current no-Prisma decision: the reviewed privileged database connection bypasses RLS and the pooled runtime/access model has not been validated. Start product search with PostgreSQL indexes and exact SKU/model matching. Consider [Meilisearch Community Edition](https://github.com/meilisearch/meilisearch) only if measured catalog needs justify another service: CE is MIT, while enterprise features are governed separately by commercial terms/BSL 1.1. [Typesense Server](https://github.com/typesense/typesense) is GPL-3.0 and is excluded from the strict-MIT shortlist; its client libraries have different licenses, so do not infer the server’s license from them.

## Commerce and CMS templates reviewed

These are reference material, not candidate dependencies for the selected custom InsForge architecture. [Vercel Commerce](https://github.com/vercel/commerce) is MIT, but was archived on 20 October 2026 (14.3k stars / 5.5k forks); its Shopify-oriented starter is useful only for structural comparison. The older [Medusa Next.js starter](https://github.com/medusajs/nextjs-starter-medusa) is MIT but archived 2 July 2026 (2.8k / 1.0k), so avoid starting new work there. Medusa’s newer DTC starter is active, but its separate commerce backend is outside the confirmed InsForge plan. [Payload’s ecommerce template](https://github.com/payloadcms/payload/tree/main/templates/ecommerce) is MIT and its current source describes the template as beta; it brings a different CMS/storefront model and is not adopted. None of these template statuses or popularity numbers imply endorsement or PandaByte compatibility.

## Proposed visual recipe

Use the selected precise, spacious engineering-studio direction: real board and kit photography, strong product specifications, clear calls to action, and restrained decoration. A possible token starting point is the current design proposal: light background `#F7F9FA`, surface `#FFFFFF`, text `#15212B`, secondary text `#52616B`, accent `#007B8A`; dark background `#0E151A`, surface `#151F25`, text `#F1F5F7`, secondary text `#B0BDC5`, accent `#54D5DF`. The sampled light accent has 4.73:1 contrast against the light background, and dark cyan has 10.48:1 against the dark background. These are draft tokens, not final branding: validate every real text/control state, focus ring, disabled state, chart, and photograph overlay for WCAG contrast in both themes.

Use a system sans stack and system monospace for model numbers, SKUs, and code unless a custom face is approved. If Inter is chosen, its font files use the [SIL Open Font License](https://github.com/rsms/inter/blob/master/LICENSE.txt), not MIT. Keep motion short and functional: roughly 120–180 ms for hover/focus feedback and 180–260 ms for drawers or accordions. Prefer color/opacity and a small transform; honor `prefers-reduced-motion`, and never make essential information depend on animation. CSS is enough for routine transitions; optional Motion should earn its bundle and complexity.

The site’s commerce, company, careers, tutorials/blog, and future open-source pages can share these tokens and selected primitives. Launch the community-facing area as a curated projects/resources hub with verified repository URLs, statuses, and licenses; a forum, LMS, or member discussion system remains separate future scope. No brand name treatment, final palette, font, template, or additional service is decided by this ledger.
