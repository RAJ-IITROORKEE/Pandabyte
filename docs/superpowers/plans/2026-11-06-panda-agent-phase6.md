# Panda Agent Phase 6 implementation plan

6 November 2026. Authorized resumed phase on `codex/panda-agent-fastapi-replacement`, following Phase 5 code `a1c5b14` and closeout `1359f95`. This is the Agent brief's Phase 6, not the storefront roadmap. No commerce, public deployment, push or IAM change.

## Frozen interfaces and ownership

Root owns application integration, SQL, dependencies, private service deployment and verification. Terra baseline owns only the new Python MCP modules/tests; Terra evidence owns only new `src/agentic/` modules and their tests. Sol independently reviews contracts, integrated changes and acceptance. UI design must use the existing approved page families and an actual reviewed Superdesign extension before substantive implementation.

1. **Restricted MCP fetch.** Review/pin the educational Fetch reference at `36380287ed3b15d115b55f546617d723072b1296`; do not copy its ambiguously scoped source or ship its unsafe default network/parser stack. Use original application code with the MIT official SDK 2.3.0, exact wheel pins and retained dependency notices. Genuine stdio initialize/list/call invokes HTTP in a child. `fetch_document(document_id)` returns a frozen typed document or a finite sanitized error; cancellation propagates and reaps the child. The only initial catalog entry is the already reviewed ESP32 GPIO ESP-IDF 5.5.1 URL. Fixed URL, public resolved addresses, actual peer-pinned TCP/TLS, identity encoding, HTML only, 256 KiB, no redirects, at most robots + page, 10-second whole operation, one child, clean environment. No arbitrary user URL/log/image goes to the child. Reference licensing/transport limitations are recorded, not hidden by calling this a fork.
2. **Finite controller and helpers.** Public structured input selects one of exactly three bundled skills and an explicit task (`mcu-comparison`, `firmware-gpio`, `project-outline`), at most two exact product SKUs, question and optional bounded user-reported components. The server validates product identity and freezes at most three needs. Stable child IDs derive from parent/plan/need; never reuse one single-product worker turn for two needs. `runAgentic` receives genuine canonical, external, current-grant and durable reserve/record/read callbacks. Every attempt consumes one shared four-call limit; unknown attempts are never dispatched again. The 30-second deadline starts at durable admission, not each controller reconstruction. Models/paid calls remain zero. Whole-turn context and quotes retain stricter eight-fragment/20,000-unit/four-selection/600-total-unit limits. Helpers perform dimension-checked arithmetic and user-reported BOM formatting only.
3. **Durable authority.** Add private owner-bound composite turn/call tables linked to the existing chat turn; one answer remains in the existing store. Bind exact input/plan, selected immutable skill hash/version/epoch, admitted deadline, ordered tool grants, call hashes, source scopes and terminal reason. Signed BFF RPCs reserve before execution, record bounded checked results and finalize under current scope/grant locks. A duplicate cannot refill budget; a new session cannot widen the plan. Read/replay rechecks every used source and grant epoch, replacing an obsolete answer with a fixed no-quote message. Existing single-product, guide and diagnostic validators remain strict. Public history contains only validated citations, labeled external references and small observed tool cards. Internal receipts/handles/bodies remain private. Cancel fences the parent and cancels known children; no new work on read/status.
4. **Registry/Admin/UI.** Extend the existing skill registry with `panda-documented-firmware-help`, `panda-error-triage`, `panda-project-planner`, each with two immutable reviewable versions. Existing ADMIN review/enable/disable/rollback/CAS/audit controls apply. Keep old tool controls explicitly scoped to `search_vendor_docs`; new MCP/helpers use separate reviewed manifest controls in the same registry. Effective permissions are selected skill ∩ current grants ∩ frozen plan. New features default OFF until reviewed development activation. Extend the existing assistant runtime, composer and message/source components; no second store or transport. Context7 stays OFF for unverified coverage/schema/account/quota/privacy; MarkItDown stays OFF because no approved current input requires its parser.
5. **Verification and closeout.** Run focused guard tests first, actual allowed MCP wire/HTTP and cancellation on Linux ARM under the existing private container limits, canonical QA after each integration, development SQL ownership/current-grant/source/replay races, and genuine disposable identity isolation. Freeze held-out cases before evaluation; run baseline/candidate on the same scope with support/abstention/leakage/count/latency/cost denominators. Use Codex browser for compound/two-source and version-specific journeys, real tool cards, Admin withdrawal, reload, cancellation, keyboard/mobile/long-thread. Preserve owner and old histories, clean only marked fixtures/processes, measure resources separately from Phase 7 load work, update page/phase handoffs and obtain Sol signoff before claiming PASS.
