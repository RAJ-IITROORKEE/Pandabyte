# Admin order management — development work, 28 October 2026

The Orders list and detail use the existing Mono admin shell. The list calls `admin_search_orders`, a staff.manage-protected read-only RPC with bounded search, pagination, sorting, payment/status/environment and India-time date filters. Statistics are calculated over the selected environment and date range, independently of search and status filters; each environment is separate. Pending includes unconfirmed/review states, active covers eligible processing and fulfilled orders, cancelled covers cancelled operations, and failed/cancelled payment exceptions remain visible in All. Delivery confirmation does not exist in the model, so Delivered is explicitly zero and Fulfilled is not relabeled. Legacy rows have no supported detail endpoint and are marked accordingly.

Detail reads the existing versioned order endpoint and a separate `admin_get_order_activity` projection requiring staff.manage. Its capped, allowlisted activity excludes raw audit data and opaque identities. The UI uses stored purchase/contact/address snapshots; missing historical product images, previous status/reason, delivery and provider references are not invented. Status choices mirror existing simulation and paid-test rules. Review orders are read-only in this UI. The server remains the source of truth for transitions, payment and inventory effects. Internal notes are not currently supported by the writer.
