# Native Agent workspace implementation

The existing assistant-ui runtime remains the sole message/composer owner. The workspace reads the private capabilities endpoint, validates its bounded response, and shows the effective model, readiness and native allowance as read-only information. In native mode, an absent, invalid or unavailable response disables new submission while preserving saved chats and recovery controls. The capability response is refreshed after a run changes state. Starter prompts cover general embedded questions, planning and a BOM without presenting inferred product facts as verified.

Unavailable search and attachment controls were removed from the composer. Voice privacy remains accessible through a compact disclosure. Account settings are labeled separately, and memory copy distinguishes saved history, project memory and native working context. Existing saved citation/tool cards, archive and cancel/recovery behavior remain; the old prose-inferred external reference is suppressed in native mode. No new runtime events, MCP or child execution are claimed. Structured answers remain plain text until a validated, persisted artifact event contract exists.

Validation: capability parser tests and scoped ESLint passed; `npx tsc --noEmit --pretty false` passed. Browser, live capability/API integration, small viewport, focus and actual streamed native runs remain for the integration owner. A user explicitly waived the prior Superdesign review requirement for this implementation; the existing draft remains untouched.

The owner subsequently requested a compact sidebar: Memory & context, Account, Account settings and the existing theme toggle now live in the existing account menu. The selected identity, avatar and logout are retained. Escape returns focus to the account-menu trigger; selecting Memory closes the mobile sidebar and focuses its heading. This navigation update passed scoped ESLint and TypeScript checks; browser focus and mobile rendering remain to be verified.

The chat column and composer now share a 960px maximum width, with the existing mobile gutters. A working shimmer appears only while a request runs and uses the existing reduced-motion-aware Shimmer. The optional page-local queue accepts up to three follow-ups for one created chat, displays and removes them, and dispatches FIFO only after the preceding request completes with the chat idle. Stop or an unconfirmed outcome pauses the queue; selecting a different chat pauses it, and explicit resume requires the original chat to be selected and reconciled. Queue data is not durable across reload. Backend admission remains authoritative. Queue unit tests cover bounds and chat matching; asynchronous browser cancellation/reconnect and complete multi-turn integration still require the integration owner.

Native dispatch also checks current capability readiness at the `sendMessage` boundary before adding an optimistic message. The workspace is keyed by Clerk user ID so an account change unmounts and clears the page-local queue. Native mode explicitly says each request is independent and saved chat history is not included in its current context.
