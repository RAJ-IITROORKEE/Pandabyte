### Frozen private authority contract

Binding is `{binding:hex64,owner:hex64,sessionID:nativeSessionID,profileHash:hex64,imageId:sha256,created:epochMs}`. Owner/binding hashes are server-derived private ownership references, not browser credentials or raw subjects. A caller must authenticate independently before using the authority. Run receipt is `{binding,owner,runID:UUID,messageID:nativeMessageID,promptHash:hex64,generation:hex64}`. Operation is `{kind:'primary'|'tool',key:hex64,requestHash:hex64}` derived by the trusted gateway/broker, never browser input.

- `openResearchRuntimeStore(root)` validates an absolute private, non-symlink directory and returns the authority. All keys/receipts are revalidated and copied. Unix root/files must have no group/world access; Windows offline tests cannot establish Unix ownership.
- `createBinding(binding)` exclusively writes immutable ownership/profile identity. Identical creation is observable, changed/foreign creation conflicts.
- `startGeneration(binding,expectedGeneration|null,newGeneration)` serializes compare-and-set. On first start it installs the generation; later rotation preserves native history and marks any active run interrupted/unknown with no egress grant. It cannot free an unresolved run for new work.
- `admitRun(receipt)` requires the current generation, matching immutable binding and no active/unknown run. It stores the run before native prompt admission. A duplicate receipt returns existing state; it does not authorize another prompt POST. `claimOperation(receipt,operation)` requires the current active run, no unresolved operation and a fresh key/digest. It persists/fsyncs the claim before returning `dispatch`; identical settled returns `cached`; identical claimed returns `unknown`; changed/foreign/stale returns `conflict`.
- `settleOperation(receipt,operation,result)` validates bounded plain JSON, persists the private result and its digest before marking settled. Only the exact claimed operation can settle once. A mismatch cannot rewrite a result. Failure to persist leaves it unknown. `recoverOperation` observes the same states without dispatch/current-generation activation; an old generation can read only its own receipt's result, not mutate or reopen it.
- `current(receipt)` is false after cancel/rotation/retirement or foreign identity. `finishRun(receipt,outcome)` is called only after the runner verifies owned native idle/outcome and every attempt is settled; it releases admission only for that finished receipt. An unresolved claim cannot be cleared by calling finish. `reconcile(binding)` returns private recorded state and never posts a native mutation.

Use an exclusive per-binding filesystem lock and durable atomic snapshot writes; do not automatically remove a lock left by a crashed process. Claims/results survive process restart. Keep each run in its own bounded file so a long testing history does not require rewriting an ever-growing chat manifest. The root is a host-owned private execution fence; D adds cross-instance/database ownership and canonical evidence, rather than replacing this host fence with a second history engine.

## Contract freeze after the first readiness review

The first reviewer found five Major gaps. These rules replace less specific wording above.

### 1. Deterministic primary continuations

B permits a primary model call initially and after a settled native tool step. It does not admit arbitrary text-only extra continuation, output recovery, title, generation or compaction calls. Those kinds are explicit denied synthetic tests; F later adds their separate reviewed identity/accounting contract.

Canonical JSON recursively sorts plain-object keys, preserves array order and JSON primitive values, rejects nonfinite/unsupported/accessor/cyclic values and hashes UTF-8 serialization with SHA-256. The request digest includes the entire reviewed provider JSON body, excluding transport headers. Request-digest lookup precedes frontier lookup: an identical digest from any attempt of this run can only return its settled stored response; a claimed/sent/unknown digest never dispatches. Changed request bytes under an existing frontier conflict. An unresolved operation anywhere in the run blocks another dispatch, even under a new frontier/digest.

The initial frontier is `{v:1,messageID,steps:[]}`. Require exactly the admitted current user text hash and no current assistant record. Older completed turns are prefix context, not this run's steps. Once the first response settles, its stored normalized result contains exact emitted tool calls `{id,name,inputHash}` or a final stop/text result. Stop/text does not authorize another call in this run.

Before a tool-result continuation, match every emitted call ID/name/input hash to exactly one raw current native tool; all calls must belong to the same completed native assistant and have completed/error status. No extra/duplicate/foreign tool, later user or unresolved tool is allowed. Persist that prior attempt's assistant association once; a later different association conflicts. The new frontier appends `{attemptKey,assistantMessageID,calls:[{id,name,inputHash,status,contentHash}]}` with calls in the emitted response order. `contentHash` hashes the exact normalized native text-content array (empty for error), not timestamps/reasoning/metadata. All preceding associations must still match; no attempt can skip or reorder a native step. The outgoing provider messages must contain the exact prior assistant call IDs/name/arguments and tool-role result IDs/content for those native results. This check prevents a body from claiming a tool result that the broker/native session did not produce. The host chooses no next tool; it validates native continuation.

Tests freeze these frontiers, including replay before/after lazy assistant publication, settled-response replay with a changed observed frontier, a changed-body retry at the same frontier, an unresolved attempt plus a new frontier, two emitted tools, valid continuation, duplicate association and forbidden stop/text continuation.

### 3. Cancellation and current-source checks

Add `cancelRun(receipt,reason:'cancelled'|'source_retired')`. It records a permanent egress/release fence under the same binding lock, without deleting attempts. Add `markSending(receipt,operation)` to serialize the final durable dispatch admission with cancellation. It verifies the claim, generation, run flags and fresh currentness, fsyncs `sent`, then returns a private one-use `{grant:hex64}`. The trusted transport calls it immediately before physical send, without another asynchronous preparation step. Cancellation recorded before this point denies dispatch. Cancellation after it means an already admitted in-flight operation: signal abortion is best-effort, its claim remains unknown unless a verified result settles, and release is forbidden. Do not promise the provider can be uncharged or retract a request already admitted. Claim, send and release require currentness. **Settlement is the deliberate exception:** `settleOperation(receipt,operation,grant,result)` may record the exact already-sent verified result after cancellation, source retirement or generation rotation.
