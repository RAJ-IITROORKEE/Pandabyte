## Readiness review 1 (Claude Sonnet 5.5 medium Goldfish) and resolutions

The first review verified every catalog fact but found one Blocker and four Majors; all are resolved by the "Revisions" section below, which overrides the original Design where they differ.

- **Blocker, per-call reservation:** `reservation` (1,410,001 nano-USD) at `research-openrouter.ts:9` and the gateway `validResult` cap at `research-provider-gateway.ts:45` are GPT-OSS-sized; full-prompt Luna, Haiku and any non-trivial Terra call would be rejected as unknown. → R1.
- **Major:** `matchResearchStopResult` calls `validResult(attempt.result,'tavily-hosted')` (`research-provider-gateway.ts:209`), ignoring the actual profile. → R2.
- **Major:** the proposed bound drops GPT-OSS's cached-token discount, so GPT-OSS would not be byte-identical; Haiku's 1h cache-write rate was ignored. → R3.
- **Major:** prefix tag matching yields three `amazon-bedrock*` rows for Haiku. → R4.
- **Major:** Haiku reasoning/`max_tokens` 700 compatibility, `reasoning_details` and possible `cache_control` keys undecided. → R5.
- Minor/structural: live-path signatures, unverified history-ID rule, cross-worker interface, GPT-OSS golden policyHash, driver fixtures. → R6–R10.

## Revisions (authoritative)

- **R1 Per-model reservation.** Each descriptor carries `reservationNanoUsd = ceil((maxInput × maxInputRate + 700 × completionRate)/10) + 1` with `maxInput` the existing research input bound and `maxInputRate = max(prompt, cacheWrite, cacheWrite1h)` in tenths of nano-USD. Approximate per-call ceilings at the current input bound: Luna ≈ 2.6M nano-USD (~USD 0.0026), Haiku ≈ 3.6M (~USD 0.0036), Terra ≈ 25.9M (~USD 0.026); a run has at most 4 calls. These are execution guards derived from catalog prices, not an application spending cap; no cumulative cap is added. `research-openrouter.ts` and the gateway's `validResult` use the selected profile's descriptor reservation; GPT-OSS keeps 1,410,001 exactly. The reservation lookup is exported from `hosted-model-policy.ts` (owned by Worker A) and consumed by the gateway (Worker B) through the frozen interface in R9.
- **R2 Profile-true reconciliation.** `matchResearchStopResult` and its `deriveResearchFrontier` caller take the run's `profile` explicitly and pass it to `validResult`; a missing or non-hosted profile fails closed.
- **R3 Cost bound.** Keep `validateHostedUsage(value,maxInput,reservation)` and its GPT-OSS formula untouched (live main-chat path and GPT-OSS research unchanged). Add `validateHostedResearchUsage(descriptor,value)` for the new models: bound = `ceil((prompt_tokens × maxInputRate + completion_tokens × completionRate)/10) + 1`, capped by the descriptor reservation; `cached_tokens` and `cache_write_tokens` allowed; any 1h cache-write reporting is covered by `maxInputRate` including `input_cache_write_1h`. A golden test pins GPT-OSS bounds/usage results to current values.
- **R4 Exact tags.** New descriptors match catalog and ZDR rows by exact `tag` equality and require exactly one of each. GPT-OSS keeps today's prefix/variant behavior inside the untouched `approvedHostedEndpoint`; new models use a new `approvedHostedResearchEndpoint(descriptor,catalog,zdr,maxInput)`.
- **R5 Haiku decisions.** For Haiku the wire omits `reasoning` and sends `include_reasoning:false` (no thinking budget, so `max_tokens` 700 is compatible and no `reasoning_details` need echoing); Luna/Terra keep `{effort:'low',exclude:true}`. The stream parser keeps rejecting non-empty `reasoning_details`. `validResearchProviderBody` stays exact-key: if native OpenCode emits `cache_control` or any other extra message key for a profile, the body fails closed before any POST; the injected native run per profile asserts the exact outgoing message keys so this is discovered offline, and any allowance is a separately reviewed change.
- **R6 Live path untouched.** `approvedHostedEndpoint`, `validateHostedUsage`, `hosted-model-openrouter.ts` and `luna-rag-openrouter.ts` signatures and behavior are unchanged; only new functions are added.
- **R7 History IDs as descriptor data.** Descriptors carry `historyIdMax` (40 for `openai/` per the observed OpenCode behavior, `null` for Anthropic) used by the gateway in place of the GPT-OSS literal at `research-provider-gateway.ts:129`. The injected run per profile emits one 64-character call ID and one containing `.`/`:` so truncation/sanitising is exercised; if native behavior differs from the descriptor, the descriptor follows observed behavior after review.
- **R8 Golden GPT-OSS identity.** GPT-OSS `policyHash`, profile hash and wire body remain byte-identical to pre-change values; descriptor fields are added to `policyHash` only for new models. Golden tests record the current GPT-OSS values before edits.
- **R9 Frozen cross-worker interface (written before workers start).** `research-profile.mjs` exports profiles `tavily-hosted-luna|terra|haiku` whose `modelID` is the catalog id. `hosted-model-policy.ts` exports `hostedResearchModels` (frozen map by model id) and `hostedResearchModel(modelID)` returning a descriptor `{id, reportedModels:[id, datedSlug], endpointTag, providerName, endpointName, tokenizer, outputParam, reasoning:'low'|'omit', historyIdMax, pricing, pricingKeys, overrideKeys, maxPrice, rates:{prompt,completion,cacheRead,cacheWrite,cacheWrite1h}, reservationNanoUsd}`. Observations record the endpoint tag; receipts record the provider name; both come from the descriptor. Worker B may stub the policy import until A lands; root merges and runs combined tests.
- **R10 Driver.** Root updates `scripts/test-native-research.mjs`/`test-native-model.mjs`: a `--profile` option, catalog/ZDR/SSE fixtures generated from the descriptor (tag, provider name, dated slug), a Haiku `cache_write_tokens` usage case, and assertions on wire `model`, `provider.only`, output param name and exact outgoing message keys.
- **Type widening:** `research-runtime.ts:11` union, the cast at `research-binding/index.ts:30`, profile JSDoc, and the GPT-OSS literals in `research-openrouter.ts` (`:26`, `:30`, `:91`, `:93`, `:165`, `:186`, `:199`, `:243`, `:246`).

## Design (original; see Revisions above where they differ)

1. **Profiles.** Add native profiles `tavily-hosted-luna`, `tavily-hosted-terra`, `tavily-hosted-haiku` to `researchProfileSelection` (`runtime/opencode/research-profile.mjs`). Each is identical to `tavily-hosted` (same tool, path, timeout, providerID `panda-research-hosted`, output 700, usageMode `hosted`, instruction, permissions, steps, limits) except `modelID`. `tavily-hosted` stays GPT-OSS and its profile hash is unchanged (regression-tested). Every existing caller already selects by profile name and the profile reaches native code via `PANDA_RESEARCH_PROFILE`, so no new environment variable or file is needed. Validators that accept `'tavily-hosted'` (runtime, transport, gateway, binding, controller, proxy, shim) accept the hosted family through one helper `isHostedResearchProfile(profile)` exported from `research-profile.mjs`.
2. **Policy registry.** In `src/server/hosted-model-policy.ts` add a frozen `hostedResearchModels` map keyed by model id with: id, reportedModels (exact allowed response `model` values: id and dated slug), endpointTag, providerName, endpointName, tokenizer, outputParam (`max_tokens` | `max_completion_tokens`), exact pricing strings, allowed pricing keys, allowed override keys, routing `max_price` (USD per million: prompt/completion = the endpoint rates, request 0, image 0), and integer cost-bound rates in tenths of nano-USD per token (prompt, completion, cacheRead, cacheWrite). The GPT-OSS entry reproduces today's checks exactly; `approvedHostedEndpoint` and `validateHostedUsage` take the descriptor (existing callers pass the GPT-OSS entry, so the live main-chat path is byte-identical). Endpoint approval rejects: wrong tag/name/provider/model, safety_retention not false, missing ZDR row, any price string change, unknown pricing/override key, override threshold ≤ max input, missing output param/`tools`/`tool_choice`/`reasoning`/`include_reasoning`/`response_format`, `tool_choice.none`/`auto` not true, status ≠ 0, implicit-caching value ≠ catalog value, context/max-completion/max-prompt below bounds.
3. **Usage and cost.** `validateHostedUsage(descriptor, …)`: completion details allow `reasoning_tokens` (others must be 0 as today); prompt details allow `cached_tokens` and `cache_write_tokens` (Anthropic reports cache writes), `audio_tokens`/`video_tokens`/`image_tokens` must be 0 in C3. Upper cost bound (nano-USD, ceiling) = `ceil((prompt_tokens × max(promptRate, cacheWriteRate) + completion_tokens × completionRate) / 10) + 1`, capped by the per-call reservation; reported `cost` above it is invalid. This is deliberately conservative (it never under-bounds a cache write) and keeps the existing nanoCost parser.
4. **Transport.** `createResearchOpenRouter` takes the profile (default `tavily-hosted`) and resolves the descriptor from its `modelID`. Wire policy per model: `model`, the descriptor's output param set to 700, `provider:{only:[endpointTag],allow_fallbacks:false,require_parameters:true,zdr:true,data_collection:'deny',max_price}`, unchanged reasoning `{effort:'low',exclude:true}`, `include_reasoning:false`, usage include, plugins [], `tool_choice:'auto'`, `X-OpenRouter-Cache: false`. Metadata fetch uses `/models/<id>/endpoints`. Stream identity accepts only the descriptor's reportedModels and providerName; receipts and observations record the actual model id and provider (types widen from the GPT-OSS literals to the allowlisted union). `policyHash` includes the full descriptor. The 14,000-byte wire bound, 512,000-byte stream bound, maxCalls 4, metadata eligibility, one-use preparation and no-retry/no-fallback rules are unchanged.
5. **Tool-call history IDs.** The gateway currently compares outgoing tool-call IDs truncated to 40 characters only for GPT-OSS. OpenCode 2.2.5's shortening was observed for `openai/` model IDs; apply the existing truncation rule when `modelID.startsWith('openai/')` and not for Anthropic. The injected native run per model must confirm actual OpenCode behavior before acceptance; if it differs, the rule follows the observed native behavior, not this assumption.
6. **Output budget risk.** All three are reasoning models; 700 output tokens include reasoning. Keep 700 (same as the live Luna path) and record measured reasoning/visible tokens in the real tests; any change is a reviewed policy edit.
