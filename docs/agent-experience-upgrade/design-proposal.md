## Direction and audit

One conversation column is the focus. Customer history and account controls live in a collapsible rail; a compact composer remains at the end of the thread. Admin keeps a separate shell with three destinations: the existing RAG Control, Agent Skills and Playground. Borders and restrained emerald accents distinguish controls from neutral surfaces. The prototype uses the unchanged `public/brand/pandabyte-logo.png` with a white backing, and colors from `components/admin/admin-theme.module.css`; system fonts are used locally because the prototype must make no network requests. Production Admin retains the approved Outfit typography and scoped tokens; customer styling remains independently scoped.

The current customer page wraps `PandaAgentWorkspace` and passes feature gates for guides, diagnostics, agentic behavior and management. This proposal removes mandatory mode selection from the customer interaction; it does not delete those capabilities or change their access. The existing Admin control room combines intake, inspection, corpus, skills and evaluation. It explicitly states that external link intake saves metadata without fetching and evaluations are disconnected. The proposal organizes those concerns without claiming these unavailable functions now work. Existing role, version, rights and review guards remain mandatory.

A local HTML draft is used because the current task prohibits external uploads and paid Superdesign calls. No Superdesign canvas or external visual review is claimed. The draft is self-contained except for the exact local logo, makes no external requests, and is a design artifact only. UI/UX Pro Max, frontend accessibility and React performance guidance informed hierarchy, accessible controls and reuse; no new component library or runtime was installed.

## Page and state specification

- **Customer:** a rail contains New Chat, Search Chats, history, Memory & Context, Settings and Account; mobile uses a menu-controlled rail. The thread illustrates Markdown/list and code presentation, copy actions, citations and expandable safe activity, with a bounded scroll region and composer anchored in view. The state selector illustrates empty, streaming, interrupted and error states in addition to an example answer. In production preserve drafts, ownership, history, cancellation and recovery. Send becomes Stop only during an active request. Attachments, upload previews/status, voice and model choice appear only when actually supported and authorized. The preview deliberately does not implement these actions.
- **Memory, settings and account:** memory review/correction/deletion require the real owner-scoped service and documented data flow; development memory never appears here. Settings show only supported preferences. Identity/account actions remain with existing account services.
- **RAG Control:** five sections cover Knowledge Sources, Review & Publication, Retrieval Testing, RAG Evaluations and Diagnostics. Show actual ingestion, chunk, approval/version and audit states; retrieval citations and scores only when available. Evaluations and diagnostics display measured results, failures and insufficient evidence without fabricated metrics. Withdrawals must propagate to subsequent answers and caches. Reuse the existing controls and shared authorized RAG path.
- **Agent Skills:** four sections cover Skills, MCP Servers, Tools and Configuration. Show real source, availability and validation; MCP transport, verified connectivity and discovered tools; tool origin and effective permissions; and only genuinely supported harness configuration. Secret inputs are write-only references, never raw displayed credentials. Unsupported operations have explicit explanations; any external installation or side-effecting tool requires the verified supported flow and appropriate authorization.
- **Playground:** use the same conversation patterns and execution/RAG services in a dedicated Admin-only test scope. The compact configuration identifies only supported model, skill, MCP, tool and RAG selections. The optional inspection area shows actual request, model, permitted tool/skill activity, retrieval/citations, errors and measured usage where available. Never show private reasoning, credentials or sensitive payloads. Reset affects only the isolated test session; side effects require appropriate confirmation.

## Responsive and accessible implementation contract

At desktop widths the rail is persistent, conversation width is capped for reading, and the Playground's inspector is beside the thread. Below 760 CSS pixels the rail is toggled by a labeled menu, section navigation scrolls horizontally, and the inspector stacks below the conversation. The design must remain usable at 320 CSS pixels and 200% zoom without obscuring the composer or causing page-level horizontal overflow. Verify 320, 768, 1024 and 1440 CSS pixels in light and dark themes.

Use semantic headings, landmarks, labeled form inputs and buttons; a real tab pattern must support arrow keys and selected/focus states, or use ordinary navigation buttons with clear current-state announcements. Mobile drawers and dialogs must trap focus when modal, close with Escape and return focus to their trigger. Maintain visible keyboard focus and minimum 44px touch targets, announce loading/errors and meaningful streaming state changes without announcing every token, and preserve focus after sends and recoveries. Citations and tool details must be keyboard accessible. Meet WCAG contrast for text and controls; verify forced colors and reduced motion. Do not rely on color alone for status. Prototype controls are illustrative and do not establish accessibility conformance.
