# Fresh lightweight Panda Agent replacement contract

Latest owner steering, 5 November 2026. This supersedes the earlier proposal to repair or reuse the existing Panda Agent orchestration harness. The owner requests a fresh agent and Docker/FastAPI runtime on a **separate feature branch**, preserving the existing UI, and AWS CLI hosting/connection to the current system. The owner selected: **reuse the existing Panda Agent AWS host, if capacity permits**. The eight-phase brief still governs delivery; finish Phase 1 before automatically starting Phase 2.

## Scope and preservation

- Build a fresh, bounded coordinator and remove old OpenCode/native orchestration from the replacement branch's active server call path. Do not patch or import the legacy native/attestation/hosted orchestration stack as the new runtime.
- Preserve the approved product RAG, canonical corpus, rights/revision/generation controls, Clerk identity, user-scoped InsForge access and durable customer history. These are evidence/data/security boundaries, not permission to reuse the old harness. No reingestion, copy/re-embedding of private documents, grant widening or authentication bypass to obtain a pass.
- Preserve the assistant-ui runtime as the sole client message-state owner and keep the visible layout, branding and components. Server progress/model labels must describe actual execution; remove or correct obsolete claims while preserving appearance. No second chat store/composer/stream or development agents for customer requests.
- Preserve main, the baseline branch/worktree, old deployments, AWS data/volumes/history and existing service configuration. Source removal on a separate replacement branch does not authorize cloud teardown, deleting data, resizing or stopping the existing gateway. Checkout, payments, invoices and unrelated storefront/Admin behavior remain outside the diff.

Root must create/verify the separate replacement branch before runtime edits and record its actual name, base and worktree in the handoff. The existing baseline branch is the control; no release-branch wholesale merge or dirty-source wholesale copy. Any selectively adopted schema/helper has an explicit reviewed provenance/diff, with Root as sole migration/integration owner.

## Minimum integration contracts

1. Keep `/panda-agent` and the existing same-origin customer chat endpoints/public DTOs where practical. Clerk-derived actor and active session, same-origin mutation checks, bounded exact inputs, owner checks and private/no-store responses remain in the Next.js BFF. Never accept client actor/role/subject or a public worker endpoint as authority.
2. Route the replacement BFF to fresh lightweight server modules, not old `local-runtime` / `opencode-selector` / native hosted executors. Retain existing public thread/message shapes, citations and bounded genuine progress where compatible; normalize worker results once in the trusted BFF. Existing source-map failures and required source-save/replay fixes remain acceptance cases.
3. Keep canonical retrieval in its TypeScript owner, lexical by default. Reuse `answerQuestion` and checked InsForge projections, their eligibility-first ranking and literal server-built citation DTOs. Send only bounded, question/turn/scope-bound fragments to private FastAPI through the trusted selector seam. No database credential, broad user session, Admin/private search, shell or unrestricted network tool enters model context.
4. Use one small async FastAPI coordinator and one allowlisted product-evidence capability first. Bind short-lived authenticated capabilities to turn/user/session, question/scope/fragment digests, action, audience, expiry and nonce. Enforce one-use/replay protection, bounded input/output/time/concurrency, cancellation and explicit terminal outcomes. Ordinary factual turns target at most one model call; no speculative multi-agent runtime.
5. Preserve durable request uniqueness, finish authority and owner-scoped history. Current session/source rights must fence save, final publication, reload and replay, including withdrawal races. Pending unknown provider outcomes cannot trigger blind retries or a second spend; summaries cannot revive withdrawn evidence or grant rights.
6. New-provider mode is zero-paid/free-only: versioned server allowlist, verified current price/privacy/modality/compatibility and hard zero monetary allowance for calls, retries and fallbacks. Unknown pricing or exhausted/incompatible quota returns honest unavailable. An AWS host authorization does not approve paid inference, transfer existing paid ledgers into the new allowance, or enable paid fallback. Report measured free quota and compute hosting costs separately.
7. The replacement branch's server-owned switch OFF yields an honest disabled/unavailable state. ON selects the fresh lightweight path. **Neither state silently calls the legacy harness.** This explicitly supersedes the original default-falls-back-to-legacy proposal for the replacement branch. Rollback uses the preserved prior branch/deployment/configuration through a reviewed release operation; legacy orchestration need not remain imported into the replacement source.
