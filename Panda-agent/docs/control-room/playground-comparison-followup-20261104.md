# Playground comparison and usage follow-up — 4 November 2026

This checkpoint prepares the Admin application for guarded product evaluation. It does not enable a host profile, provision a model allowance, change a database, or deploy the website.

## Application changes

The Evaluation view can select models from the real OpenRouter catalog, with GPT-4o-mini selected initially. A comparison accepts one to four distinct model operations, each with a fresh canonical UUID. The server admits the entire requested model list against trusted configuration before preparing context or dispatching anything. The current adapter permits only GPT-4o-mini; catalog selection and advertised rates do not authorize other models.

Comparison preparation uses the existing canonical retrieval pipeline once. Every nested evaluation must match both the ordered passage text and a private proof binding the product, current scope fingerprint, chunk handles, text hashes and source metadata. Identical text from a different product or source is rejected before model execution. Fresh Admin and source checks surround each operation and the final response. Withdrawal or access loss withholds protected results. Unknown outcomes stop further dispatch and remain in the browser's pending-operation guard; they are never retried automatically.

Product responses may carry independently validated usage after durable settlement and final authorization. Input/output tokens and conservative guard-accounted nanoUSD become metrics only when present and valid; unavailable metrics remain null. Legacy mini responses retain their old shape. Both interfaces label cost as guard-accounted and distinguish it from a provider invoice. The answer area continues to display the actual validated answer when one exists; retrieval-only runs explicitly report that no model was called.

The product connection requires the exact additional server readiness flag. Comparison execution remains unconfigured when the reviewed product connection is absent. None of these flags were enabled by this checkpoint.

The product-only receiver rejects the local acceptance marker, so the application also refuses to advertise product evaluation through that unsupported local transport. Local retrieval remains available. A later local product validation receiver needs its own reviewed owner lease; the old mini lease does not enable this profile.

## Separate receiver and remaining gates

The working host/relay source has a separately reviewed product-only receiver candidate. Its proposed future31 process rejects native v1/v2/RAG, status, streaming and local-acceptance requests, and does not construct native guards. It is not a transparent replacement retaining native availability. The active native source candidate is separately pinned by the Research chat; it must not be rebuilt from the moving working directory. A future receiver package must be derived from the actual deployed baseline and must verify the same canonical host admission directory. No working relay template is evidence of deployed Lambda support.

The last verified shared authority has 23 admissions accounted, zero pending financial reservations and a cumulative 358,259,188 nanoUSD ($0.358259188) under the original $2 cap. The admission count is exhausted even though dollars remain. A separate concrete allocation, durable forward transition and finite owner validation window are required before more real model calls. Future31 is a source constraint, not approval of eight calls; a subsequently approved native allocation would require a newly compatible product plan.

Uploaded documents already have private ingestion, version-bound inspection and per-document lexical retrieval. A standalone uploaded-context preparer has offline coverage, but automatic global uploaded-document retrieval and model answering are not connected. They require a bounded Admin-only candidate projection and their own context/provenance admission contract; uploaded text must not be disguised as an approved canonical product scope. Multiple-model execution beyond GPT-4o-mini likewise requires reviewed model, price and guard policies. Live answer/citation acceptance and any measured latency improvement remain unverified for this new candidate.
