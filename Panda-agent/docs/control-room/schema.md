## Relations and invariants

- `public.panda_agent_intakes`: immutable server-generated UUID reference, derived internal object key, creator TEXT subject, actor-scoped idempotency key and server-computed input fingerprint. Metadata is bounded; uploads require exact allowed extension/media-type pairing, expected SHA-256 and size 1–3,145,728 bytes. Links pass HTTPS public-DNS **syntax** validation with no network/DNS execution. No IP literals, credentials, queries/fragments, local/private-name suffixes, backslashes or non-443 ports.
- `public.panda_agent_intake_events`: append-only versioned action/reason/status audit with database/request-derived actor and time. No customer-visible actor/object pointers, raw text or binary payloads.
- Both tables enable RLS and revoke all raw PUBLIC/anon/authenticated table privileges. No storage schema, bucket or policy is guessed/provisioned here.
- Every authenticated RPC independently calls the private genuine-ADMIN assertion. It holds `pg_advisory_xact_lock_shared(hashtextextended('staff-role-memberships',0))`, matching the existing role mutation's **exclusive** lock, then checks `requesting_user_id()` against `staff_role_memberships.role='ADMIN'`. Capabilities alone do not qualify. Role revocation must be tested under the actual request transaction isolation; normal requests use READ COMMITTED.
- Creation uses `INSERT ... ON CONFLICT (created_by,idempotency_key) DO NOTHING` plus a locked existing-row fingerprint comparison. Same payload is a no-op; a changed operation/metadata/file hash with the same key is `request_conflict`. No duplicate creation audit event. A database unique constraint arbitrates concurrent inserts.
- Expected-version row locks guard upload reports and review. Status changes are one-way and narrow; immutable identity/content metadata cannot be patched or deleted. Audit events cannot be updated/deleted.

**Source-byte integrity always remains `integrity_pending`.** Upload success is merely a reported HTTP outcome under the same user JWT; it cannot establish independent byte/readback proof. `pending_review` and `accepted_for_preparation` therefore do not mean verified bytes, parsed, indexed, eligible or published. This clarifies the earlier contract's pending-upload wording: metadata workflow may advance, but a future independent worker must verify bytes before preparation/ingestion. No worker-success receipt or integrity-promotion operation exists here.

## RPC alignment

All names below use the prefix `public.panda_agent_control_room_`. Every operation is genuine-ADMIN checked, including overview/read operations. Internal assertion, validation, DTO and trigger helpers have no PUBLIC/anon/authenticated EXECUTE grant.

| Suffix | Parameters | Result |
| --- | --- | --- |
| `overview` | none | Current canonical counts; sealed inactive/invalidated candidate counts; intake status counts; metadata ready and runtime/upload unavailable/unconfigured labels. No active-release or runtime-success claim. |
| `list_intakes` | `p_limit integer=20`, `p_before timestamptz=NULL`, `p_before_id uuid=NULL`, `p_status text=NULL` | `{items,nextCursor}`; max 50, stable descending created time/reference; cursor has `before,beforeId`. Both cursor fields must be supplied together. |
| `get_intake` | `p_reference uuid` | Safe intake DTO or `not_found`. |
| `register_link` | `p_key,p_title,p_url,p_publisher,p_purpose,p_rights_statement` (all TEXT) | Safe intake DTO, initially `pending_review`, `rightsStatus='unknown'`, `fetched=false`. No fetch. Empty optional metadata must be sent as `''`, not NULL. |
| `reserve_upload` | `p_key,p_title,p_filename,p_media_type` (TEXT), `p_expected_size integer`, `p_expected_sha256,p_publisher,p_purpose,p_rights_statement` (TEXT) | **`{intake: <safe DTO>, created: boolean}`**. Only a fresh insert returns `created=true`. A replay returns false even if the earlier upload is pending/unknown. The HTTP adapter must write bytes **only** on true; never automatically retry a replay. |
| `record_upload_outcome` | `p_reference uuid,p_expected_version bigint,p_outcome text,p_reason text` | Safe DTO; from `upload_pending` only, reports `pending_review`, `upload_failed` or `upload_outcome_unknown`. Integrity remains pending; no storage pointer parameter. |
| `review` | `p_reference uuid,p_expected_version bigint,p_decision,p_rights,p_rights_evidence,p_reason` (TEXT) | Safe DTO. From `pending_review` only; `accept_for_preparation` requires `permitted`, or `reject`. Explicit rights evidence/reason required. |

Rights enum: `unknown | permitted | denied`. Kinds: `link | upload`. Status enum: `upload_pending | pending_review | accepted_for_preparation | rejected | upload_failed | upload_outcome_unknown`.

Safe DTO fields: `reference,title,kind,status,rightsStatus,integrityStatus,createdAt,updatedAt,version,publisher,purpose,rightsStatement`; nullable `sourceSummary={url,fetched:false}`, `uploadSummary={filename,mediaType,expectedSize,expectedSha256}`, `reviewSummary={decision,reason,rightsEvidence,reviewedAt}`. No creator/reviewer subjects, object key/bucket, signed URL, idempotency key/fingerprint or raw source bytes. Opaque references are control data, not visible database-ID labels.

The private object key is derived by the database as `intakes/{reference}/source.{pdf|md|txt}`. A server upload adapter can derive that same value from its trusted reservation reference/media type without returning it in a public DTO. Dedicated private storage configuration/content validation remains root's separate observed integration task. A direct user-JWT RPC/storage call cannot manufacture a trusted worker or integrity result.

Failures use the existing `phase3_fail` detail codes: `unauthenticated`, `forbidden`, `invalid_input`, `not_found`, `request_conflict`, `version_conflict`. HTTP maps these to 401/403/400/404/409; service failure stays 503. The SQL layer never returns provider error text or generates an evaluation job. Evaluation routes remain server-known-case-set-only and 503 while execution is unavailable.
