## Actual behavior and gaps

The pinned [server implementation](https://github.com/modelcontextprotocol/servers/blob/36380287ed3b15d115b55f546617d723072b1296/src/fetch/src/mcp_server_fetch/server.py) exposes tool `fetch` and prompt `fetch`. Tool inputs are `url` (AnyUrl), `max_length` (integer 1–999999, default 5000), `start_index` (integer >=0, default 0), `raw` (boolean, default false), and `timeout_ms` (100–600000, default 30000). It returns unstructured text, not a structured output schema. Page fetch and redirects use HTTPX; the `max_length` slice occurs **after** downloading, decoding and extraction, and is a character count rather than a network-byte or memory limit. It is not a safe input-size control.

By default autonomous tool calls check robots.txt for the initial URL and redirect hops. Connection failures, 401/403 and 5xx disallow; other 4xx are treated as no rules. The user-initiated prompt bypasses robots, as does the optional ignore flag; neither should be exposed to this assistant. The [timeout implementation](https://github.com/modelcontextprotocol/servers/blob/36380287ed3b15d115b55f546617d723072b1296/src/fetch/src/mcp_server_fetch/timeout.py) states 30 seconds is HTTPX's per-phase/read timeout, **not** a total transfer deadline; robots uses its own timeout and extraction is outside it.

The [host allowlist](https://github.com/modelcontextprotocol/servers/blob/36380287ed3b15d115b55f546617d723072b1296/src/fetch/src/mcp_server_fetch/allowlist.py) is optional, host-only, and supports wildcards. The private-address hook checks resolved addresses on redirects, but the [published package warning](https://pypi.org/project/mcp-server-fetch/2026.11.4/) explicitly acknowledges a DNS-rebinding gap between resolution and actual connection and unverified proxy-only resolutions. An allowed host alone does not constrain scheme, path, port or connected peer. Never enable private IPs, proxy inheritance or robots bypass as a workaround.

The default HTML path can invoke Readability.js, and the [upstream source](https://github.com/modelcontextprotocol/servers/blob/36380287ed3b15d115b55f546617d723072b1296/src/fetch/src/mcp_server_fetch/readability_js.py) can run Node and a first-use `npm install`. `--no-readability-js` avoids that behavior, but does not solve connection pinning, total bytes, decompression bombs or extraction bounds. Upstream tool errors may include URLs, robots text and exception details; sanitize them at any public boundary.

## MCP wire

The official [2025-11-25 stdio transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) is UTF-8 newline-delimited JSON-RPC, not HTTP framing: client owns subprocess stdin, server stdout contains only protocol messages, stderr is separate. [Lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) requires `initialize` with version/capabilities/client info, result negotiation, then `notifications/initialized`; call only after negotiation. [Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) use `tools/list` and `tools/call` with `{name,arguments}`, correlating response IDs and checking `isError` and content types. [Cancellation](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/cancellation) is a best-effort `notifications/cancelled` with request ID; receiver may ignore it. Bound line length, protocol messages and stderr; reject unexpected server-to-client requests and never log source text, secrets or raw arguments.

## Proposed minimal restricted adapter — approval and implementation outstanding

The stock reference is **not ready** for this boundary. Use a reviewed narrow fork/custom transport, or a separate restricted fetch gateway that the subprocess cannot bypass, only after Root approves architecture. Enforce all destinations at the actual connection, not merely by validating the input or DNS answer in a separate step:

1. A server-owned, versioned exact HTTPS origin plus path/version allowlist of specifically approved official documentation; no arbitrary URL, wildcard, userinfo, fragment, non-443 port, IP literal, private host, model-supplied headers or credentials. The actual approved entries and source rights are still undecided. Resolve fresh on every connection; fail closed on errors/mixed public and non-public answers, IPv4-mapped IPv6, NAT64 and unusual IP encodings. Choose a validated public address and connect directly to that exact IP with TLS SNI and hostname verification for the original allowlisted DNS name; verify actual peer address. Disable proxy/environment inheritance and alternate routing. Egress policy must prevent the child bypassing this gateway, including DNS, IPv6 and redirects. A generic HTTPX request hook or hostname allowlist is insufficient.
2. Disable automatic redirects; each bounded hop is revalidated against the exact scheme/host/path policy, robots rules and newly resolved/pinned peer before any connection. Apply the same pinning and byte/deadline policy to robots, fail closed on unavailable or denied rules, and retain the autonomous user agent. No auth cookies, ambient cloud credentials or customer headers enter the child.
3. Stream and bound both compressed wire bytes and decompressed bytes before parsing; restrict content types, reject malformed encodings and oversized HTML/robots/JSON, limit redirect count, resulting text and IPC frame bytes, and give the whole operation a monotonic deadline including DNS, robots, redirects and extraction. Treat fetched content as untrusted evidence, never instructions, and validate its right/current version before citations or model context.
4. If stdio is retained, use an installed, hash-pinned executable (no `uvx`, npm or runtime installs), explicit minimal environment, fixed argv, no shell, no browser and no Node-based extraction. Only `tools/call` for the validated fixed fetch operation; do not expose the prompt or a general MCP client to customers. Send protocol cancellation then close stdin/terminate and reap the entire child process group on deadline/cancel; hard-kill after a short bounded grace. Do not assume cancellation means the remote server did not receive a request. Limit concurrency and ensure parent plus every child are measured under the same container cgroup 1 CPU/512 MiB; enforce output caps and cgroup OOM/CPU tests. No 512 MiB compliance is claimed from source inspection.
5. Fixture-test URL parsing, Unicode/IDNA, DNS rebinding and peer mismatch, mixed address families, proxy and redirect escapes, robots denial/unavailability, compressed/decompressed overflow, slow streams and extraction, JSON-RPC malformed/oversized messages, stderr leakage, cancellation and child-tree cleanup. Then verify an authorized real official page and rights against source. External traffic, deployment and scope/allowlist selection are separate gates.
