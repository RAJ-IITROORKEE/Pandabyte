# Panda Agent workspace

The authenticated `/panda-agent` route uses assistant-ui's external-store runtime with account-backed text chats, archive/restore/delete and validated source citations. The replacement service is opt-in and may be unavailable.

The composer uses assistant-ui dictation and pinned AI Elements Shimmer. Dictation depends on browser support and permission and may use an online browser service. Saved assistant messages can be read aloud using the browser's speech synthesis when available. Files are staged locally with limits and removal controls; sending them is explicitly blocked because media input is not implemented. Text answers use safe Markdown/GFM and expandable source disclosures.

The explicit server-owned `PANDA_AGENT_LIGHTWEIGHT_ENABLED` flag controls the workspace in development and production alike. OFF shows the disabled state and prevents chat API use; ON permits authenticated chat/history operations through the fresh service, subject to its independent provider readiness and all authorization/source guards. The unapproved provider remains OFF, and web search stays unavailable. Activity reports actual server stages; answer text appears only after validation and durable saving. Preserve Clerk authentication, account isolation, unknown-outcome handling and the existing source validation. A per-user sessionStorage UUID pointer may restore the active chat through the owner-scoped list and authenticated history GET; it stores no conversation text or credential.

`PANDA_AGENT_GUIDES_ENABLED` separately exposes the opt-in guide form when configured. It submits structured student intent through the same authenticated turn owner, with server-controlled versioned memory and existing cancellation/status recovery. Guides label user reports, conceptual steps and unresolved wiring; only current approved literal evidence can become a citation. Eight successful guide turns fold bounded intent memory without storing source quotes as authority. `/panda-agent/skills` reuses the reviewed ADMIN panel behind the namespaced current-session/actual ADMIN membership guard; the API/SQL enforce that role independently. A hidden account link is presentation, not authorization. Phase 4 passed with reviewed guide v1 restored/enabled at registry version 7 and the owner session/history preserved.
